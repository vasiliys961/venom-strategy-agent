# Авторские фреймворки С. Колосова, встроенные в ассистента

Этот документ описывает модели, которые Семён Колосов использует в своей
консалтинговой практике (материалы предоставлены автором). Они дополняют
общую структуру метода VENOM конкретными диагностическими инструментами.

## 1. Модель OrgOS (Organizational Operating System)

Используется на этапе **Evaluation**. Вместо абстрактных "сфер жизни"
ассистент раскладывает текущую систему на 8 связанных элементов:

1. Стратегия
2. Системы управления
3. Лидеры
4. Компетенции
5. Структура
6. Люди
7. Процессы
8. Технологии

Ключевой факт из методики: примерно **80% управленческих проблем**
возникают из 2-3 системных разрывов между этими элементами, а не из
множества разрозненных причин. решения через найм новых людей,
перестройку структуры или внедрение новых инструментов устраняют симптомы,
а не корневую причину, если сама система разрывов не выявлена.

Источник: `Diagnostika-OrgOS.pdf`

## 2. Стресс-тест стратегии (6 блоков)

Используется на этапе **Narrow gaps**. Стратегия/цель проверяется по
6 блокам устойчивости:

1. **Future Fit** — соответствует ли стратегия будущему рынка/среды
2. **Гипотезы** — на каких предположениях она строится и проверены ли они
3. **Драйверы роста** — что именно создаёт движение к цели
4. **Экономика стратегии** — ресурсная/финансовая состоятельность
5. **Реализуемость** — готова ли система (структура, KPI, процессы)
   реализовать это
6. **Устойчивость к сценариям** — что будет при неблагоприятном развитии
   событий

5 типичных ошибок, которые стресс-тест должен выявлять:
1. Стратегия строится на текущей ситуации, а не на будущей
2. Переоценка своих возможностей/ресурсов
3. Отсутствие чётких драйверов движения к цели
4. Недооценка изменений среды
5. Система (сам человек/команда) не готова это реализовать

Источник: `Stress-test-strategii.pdf`

## 3. Архитектура изменений (декомпозиция целей)

Используется на этапе **Objectives**. Переход от стратегической цели к
исполнению происходит по цепочке:

```
Стратегическая цель → Инициативы → Проекты → Структура работ (WBS) →
Приоритизированный портфель
```

Ключевой принцип: цель без декомпозиции в конкретные инициативы и проекты
остаётся презентацией — "стратегия существует отдельно, а реальная работа
отдельно". Продуктовый подход добавляет: гипотезы проверяются быстрыми
экспериментами, а не одним большим планом.

Источник: `Praktikum_Arkhitektura_izmenenii.pdf`

## 4. Стратегическая сессия (4 этапа)

Используется как общая структура графа (уже отражена в VENOM):

1. Формирование навравления развития (образ будущего)
2. Сестный анализ текущей ситуации
3. Выявление стратегических разрывов
4. Формирование стратегических инициатив

Источник: `Strategicheskaia-sessiia.pdf`

## 5. AI-first процессы

Используется как принцип на этапе **Management**: рутинные операции по
сопровождению цели (трекинг, напоминания, сбор данных для ретроспективы)
проектируются так, чтобы выполняться автоматически, а не отвлекать
внимание человека. именно поэтому сам ассистент реализован как бот, а не
как таблица, которую нужно заполнять руками.

Источник: `AI-Protsessy-i-Avtomatizatsiia.pdf`
